## Bundled binaries

### 7-Zip

ModsyncManager bundles `7z.exe` and `7z.dll` in `Assets/7z/` to
extract archives. 7-Zip is invoked as an external process
(`Process.Start("7z.exe", ...)`), not linked as a library.

- **Project:** 7-Zip
- **Website:** https://www.7-zip.org/
- **License:** GNU LGPL v2.1+, with additional BSD-3-Clause and
  BSD-2-Clause components, and unRAR license restriction.

The full license text is bundled with the distribution as
`Assets/7z/License.txt`.

**Note on unRAR restriction.** The `7z.dll` contains code derived
from the unRAR library. The unRAR license states that the code may
not be used to develop a RAR-compatible archiver. ModsyncManager
does not do this — it invokes 7-Zip only to extract archives. The
restriction does not affect ModsyncManager's use case, but is
included here for completeness.

**Note on GPL compatibility.** The unRAR restriction is not
GPL-compatible. ModsyncManager invokes 7-Zip as an external
process, not as a linked library. This satisfies the GPL's
"aggregate" clause (section 5): two separate programs distributed
together do not form a derivative work. This is the same approach
used by many other GPL projects that bundle 7-Zip.

## Compatibility summary

All runtime dependencies are compatible with GPL-3.0:

- MIT — compatible.
- Apache-2.0 — compatible with GPL-3.0 (not with GPL-2.0).
- BSD-3-Clause — compatible.
- LGPL — compatible (ModsyncManager invokes 7-Zip as external
  process, so LGPL's linking provisions do not apply).

The only license restriction in the distribution is the unRAR
restriction in `7z.dll`. ModsyncManager does not use 7-Zip for RAR
compression. The restriction does not affect ModsyncManager's use
case.
